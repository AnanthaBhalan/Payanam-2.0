feat(phase5): fix Ray Client networking; serialise @ray.remote dispatch

Ray networking -- three independent root causes, all fixed and verified.

1. Wrong port. RAY_ADDRESS targeted ray://ray-head:6379, the GCS port. Ray
   Client speaks to the client server on 10001; 6379 only serves worker join.
   Against 6379 every submission failed with "ray client connection timeout".
   The head now binds --ray-client-server-port=10001, and the published port
   is RAY_CLIENT_HOST_PORT (renamed from the misleading RAY_JOB_HOST_PORT).

2. Version and Python mismatch. requirements pinned ray[client]>=2.40, which
   resolved to 2.59.0, against a rayproject/ray:2.40.0-py311 cluster. Ray
   Client refuses mismatched versions. Now pinned to ray[client]==2.40.0 with
   the API image on python:3.11-slim.

3. Address advertisement. Both nodes pass --node-ip-address (ray-head and
   ray-worker) so the client receives a compose-routable address. The worker
   joins via the GCS port as intended.

Health now proves execution rather than reachability: ray_health_probe()
dispatches a real remote task and reads it back, reporting ready, node count
and a detail string.

Also fixes RuntimeContext.get_node_address(), which does not exist in Ray 2.40
and crashed startup.

REMAINING, stated plainly: dispatch from inside a Temporal activity still
fails with "AttributeError: InProgressSentinel object has no attribute id".
Ray Client binds its session to the calling thread and is not task or thread
safe, which is incompatible with Temporal's concurrent activity execution.
app/solver/ray_dispatch.py funnels submissions through a single-worker thread
that owns ray.init(), which is the correct shape, but does not fully resolve
it under Temporal's executor. The production fix is Ray's Job Submission REST
API on the dashboard, designed for external orchestrators such as Temporal.
That is the recommended follow-up and is NOT done here.

tests/test_ray_execution.py submits and retrieves a real remote task, asserts
solve_routing_task is remote-decorated, and asserts the dispatch pool has
exactly one worker. Skips cleanly when no cluster is reachable.

Verified: the health endpoint reports Ray ready with 2 nodes and an executed
remote task. 48 tests pass; Ray tests skip without a cluster.
